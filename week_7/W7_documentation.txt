2. TESTING THE PROGRAM & IDENTIFYING THE BUGS IN main.py
===============================================================================

I ran the original template version of main.py with different inputs.

Original main.py (template):

    def main():
        price = float(input("Price (RM): "))
        quantity = int(input("Quantity: "))
        total = price * quantity
        print(f"Total Payment = RM {total:.2f}")

Test results:

    Input (price, quantity)   What happened                      Expected
    -----------------------   --------------------------------   -----------------
    10, 2                     Total Payment = RM 20.00           OK
    abc, 2                    CRASH: ValueError                  ask again
    10, 2.5                   CRASH: ValueError (int("2.5"))     ask again

Bugs found:

  BUG 1 - The program CRASHES on non-numeric input.
          float(input(...)) and int(input(...)) raise a ValueError when the
          user types something that isn't a number (e.g. "abc", or "2.5" for
          the quantity). Nothing catches the error, so the whole program
          stops. This is the "system sometimes crashes" complaint.

  BUG 2 - The program ACCEPTS INVALID ORDERS.
          There is no check on the values. A price of 0 or less, or a
          quantity of 0 or less, still produces a "Total Payment", even a
          negative one (RM -20.00). This is the "accepts invalid orders"
          complaint.
          Python's float() also accepts the text "nan" and "inf", which
          produced "Total Payment = RM nan" and "RM inf".

  BUG 3 - main.py does the calculation itself instead of using food_order.py.
          The template has "from ___ import ___", but main() works out
          price * quantity directly. Any validation written in
          calculate_total() would never run. The logic belongs in one place.

  BUG 4 - Syntax error in the print statement.
          The template line ends with a curly quote:
              print(f"Total Payment = RM {total:.2f}”)
          Python only accepts straight quotes ("), so the f-string is never
          closed and the file won't run at all. Fixed by using a straight
          quote: print(f"Total Payment = RM {total:.2f}")

  BUG 5 - test_food_order.py calls a function that doesn't exist.
          The test calls food_order(10, 2), but the function in
          food_order.py is named calculate_total. Running pytest gives a
          NameError. Fixed by importing it under the test's name:
              from food_order import calculate_total as food_order


===============================================================================
3. DEBUGGING: THE FIXES
===============================================================================

food_order.py - validation added to calculate_total():

    import math

    def calculate_total(price, quantity):
        if not math.isfinite(price) or price <= 0:
            return "invalid price"
        if quantity <= 0:
            return "invalid quantity"
        return price * quantity

    - Price must be a finite number greater than 0 -> otherwise "invalid price"
      (math.isfinite() rejects nan and inf)
    - Quantity must be greater than 0   -> otherwise "invalid quantity"
    - Otherwise returns price x quantity

main.py - fixed version:

    - Imports and uses calculate_total() from food_order.py (fixes Bug 3)
    - read_number() wraps float()/int() in try/except ValueError and asks
      again until the input is a number, so it no longer crashes (Bug 1)
    - If calculate_total() returns "invalid price" or "invalid quantity",
      the order is rejected and the user is asked again (Bug 2)
    - The print uses straight quotes (Bug 4)
